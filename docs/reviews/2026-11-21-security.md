## 三、风险（P0–P3）

- **P0**：无。
- **P1**：无。
- **P2 S-1（新）**：`~/.dsh/guard.key` 继承父目录 ACL，`CodexSandboxUsers` 组具读权限（`icacls` 实测 `(I)(RX)`）→ C7 的「只信工具生成 manifest」被削弱：同组进程可读 key 并伪造 hmac。建议创建时用 `icacls <key> /inheritance:r /grant:r "%USERNAME%:R"`（POSIX 侧 `os.open(..., 0o600)`），并在首次自动建 key 时打印提示。
- **P3 S-2**：`GUARD_KEY` 环境变量路径无长度/熵校验（`guard_large_write.py:121-123` 直接 `encode`），弱 key 可用；且 key 会出现在子进程环境。建议最小长度 32 字节并文档说明。
- **P3 S-3**：guard key 无版本/ID，轮换后旧 manifest 全部不可校验（`load_manifest` 只认当前 key）；属可用性设计限制，建议 manifest 记 key_id。
- **P3 S-4**：`check_text.py:123` 的 `--root` 本身不校验是仓库根（只校验 `--retro`/`--git-push` 在其内）；`--root <任意目录>` 可扫描任意目录树（只读、无正文外泄）。
