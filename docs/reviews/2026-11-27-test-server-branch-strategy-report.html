2. C1 SKILL.md Step 7 加测试服务器分支策略

问题

SKILL.md Step 7 只写了"创建 PR 到 main"，没有考虑有测试服务器的场景。

改了什么

在 Step 7 加一段"测试服务器分支策略"，说明有测试服务器时先提 PR 到 test，测试通过后再提 PR 到 main。

为什么改

很多项目有测试服务器，需要先合并到 test 分支测试通过后再合并到 main。

代码对比
+ ### 测试服务器分支策略 + + 如果项目有测试服务器（查 runbook 判定），先提 PR 到 `test` 分支，测试通过后再提 PR 到 `main`。 + + 1. 创建 feature 分支（如 `fix/xxx`） + 2. 提交改动 + 3. 推送到远端 + 4. 创建 PR 到 `test` + 5. 测试通过后，创建 PR 从 `test` 到 `main` + 6. PR 创建即停，等用户审核合并
改动位置
  • ship-it/SKILL.md Step 7 节
怎么验证

检查 SKILL.md Step 7 是否包含"测试服务器分支策略"说明。

3. C2 判定方式查 runbook

问题

怎么判定项目有没有测试服务器？

改了什么

Step 2 方案自审时查 docs/deploy-runbook.md 里有没有测试服务器配置。

为什么改

runbook 是项目配置的唯一事实源，查 runbook 最准确。

代码对比
+ ### 测试服务器配置（C2） + + 查 `docs/deploy-runbook.md` 里有没有测试服务器配置： + - 有没有 `test` 或 `staging` 分支？ + - 有没有测试服务器地址？ + - 有没有测试环境部署脚本？ + + 如果有，按"有测试服务器"处理；如果没有，按"没有测试服务器"处理。
改动位置
  • ship-it/SKILL.md Step 2 节
  • ship-it/references/project-adaptation.md 检查清单
怎么验证

检查 Step 2 方案自审时是否查 runbook 判定有没有测试服务器。
