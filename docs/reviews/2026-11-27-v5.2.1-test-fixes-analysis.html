v5.2.1 测试修复 — 方案分析

1. 问题背景

v5.2.1 发布后（commit 54e560d），测试与脚本存在 7 处不同步，导致：

  • 本机（Windows 11 + Python 3.14）测试失败：7 FAIL + 4 ERROR
  • CI（Ubuntu + Python 3.11）假绿：有 FAIL 但返回 2（SKIP），被当通过
  • 中文 Windows 下 local_check.py 直接崩溃

2. 问题清单与根因分析

问题 1：测试路径硬编码（4 ERROR + 部分 FAIL）

现象：测试报 FileNotFoundError: docs/specs/2026-11-19-*.md

根因：v5.2.1 把 spec 目录从 docs/specs/ 迁到 ship-it/docs/specs/，但测试代码仍读旧路径

影响：4 个测试 ERROR（FileNotFoundError），5 个测试 FAIL（路径相关断言失败）

位置：tests/test_process_gates.py 第 1752/1769/1793/2445/2453/3002 行

问题 2：版本硬编码（2 FAIL）

现象：测试断言 version == "5.1.0"，但 SKILL.md 已是 5.2.1

根因：测试和 check_docs.py 硬编码版本号，没有从 SKILL.md 动态读取

影响：每次版本升级都要手动改测试，容易遗漏

位置：tests/test_process_gates.py 第 2758/1819 行，ship-it/scripts/check_docs.py 第 2761 行

问题 3：c18 fixture 缺 ship-it/SKILL.md（1 FAIL）

现象：check_docs 报 ship-it/SKILL.md 不存在，EXPECTED_VERSION 无法动态读取

根因：测试 fixture 只写了根 CHANGELOG.md 和 ship-it/CHANGELOG.md，没写 ship-it/SKILL.md，但 check_docs 改为动态读版本且 fail closed

影响：c18 测试 FAIL

位置：tests/test_process_gates.py 第 2193–2197 行

问题 4：run_suite 返回码语义错误（CI 假绿）

现象：测试有 7 FAIL + 4 ERROR，但 run_suite.py 返回 2（SKIP），CI 当通过

根因：run_suite.py:250-252 逻辑是"有 SKIP 就 return 2"，没考虑同时有 FAIL/ERROR 的情况

影响：CI 假绿，掩盖了所有测试失败

位置：tests/run_suite.py 第 250–252 行

问题 5：local_check 编码崩溃（中文 Windows）

现象：UnicodeDecodeError: 'utf-8' codec can't decode byte 0xbd，随后 TypeError: can only concatenate str (not "NoneType") to str

根因：local_check.py:65 用 text=True, encoding="utf-8" 但没加 errors 参数，解码失败时 stdout 为 None

影响：中文 Windows 下 local_check.py 直接崩溃

位置：ship-it/scripts/local_check.py 第 65 行

问题 6：check_docs 转义告警

现象：每次运行 check_docs.py 都报 SyntaxWarning: "\d" is an invalid escape sequence

根因：docstring 里 \d 是无效转义，Python 3.12+ 会告警

影响：日志污染，未来版本可能报错

位置：ship-it/scripts/check_docs.py 第 242 行

问题 7：测试残留 outside.md

现象：测试失败时 git status 出现 ?? outside.md

根因：test_process_gates.py:2717 写 root.parent / "outside.md"（仓库根），测试异常退出时没清理

影响：git status 不干净，需要手动删

位置：tests/test_process_gates.py 第 2717 行

3. 解决方案

方案 1：测试路径对齐

修法：把所有 docs/specs/ 改为 ship-it/docs/specs/

具体改动：

# tests/test_process_gates.py
# 第 1752 行
- spec_text = read_text(ROOT / "docs" / "specs" / "2026-11-19-contract-gates-and-concision.md")
+ spec_text = read_text(ROOT / "ship-it" / "docs" / "specs" / "2026-11-19-contract-gates-and-concision.md")

# 第 1769/1793/2445/2453/3002 行同理

为什么这么改：v5.2.1 已把 spec 统一到 ship-it/docs/specs/，测试必须跟随

影响范围：6 处路径字符串，不改测试逻辑

方案 2：版本动态读取

修法 A（推荐）：测试和 check_docs 从 SKILL.md frontmatter 动态读版本

# tests/test_process_gates.py
# 第 2758 行
- self.assertEqual(parse_frontmatter(skill).get("version"), "5.1.0", ...)
+ expected_version = parse_frontmatter(skill).get("version")
+ self.assertIsNotNone(expected_version, "SKILL.md 缺 version 字段")
+ self.assertRegex(expected_version, r"^\d+\.\d+\.\d+$", "版本号格式错误")

# ship-it/scripts/check_docs.py
# 第 2761 行
- self.assertIn("EXPECTED_VERSION = \"5.1.0\"", read_text(SCRIPTS / "check_docs.py"), ...)
+ # 删除这个断言，改为动态读 SKILL.md 版本

为什么这么改：SKILL.md 是唯一事实源，动态读避免下次版本升级再漂移

影响范围：2 处版本断言，改为动态读取

修法 B（备选）：手动同步到 5.2.1

# 把所有 "5.1.0" 改成 "5.2.1"
# 缺点：下次版本升级又要手动改

为什么不选 B：治标不治本，下次升级还会漂移

方案 3：c18 fixture 补 ship-it/SKILL.md

修法：测试 fixture 里补写 ship-it/SKILL.md

# tests/test_process_gates.py
# 第 2193–2197 行
with temp_repo() as root:
    write_text(root / "CHANGELOG.md", ...)
    write_text(root / "README.md", ...)
+   write_text(root / "ship-it" / "SKILL.md", "---\nname: ship-it\nversion: 4.6.0\n---\n\n# skill\n")
    self.assert_pass(run_docs(root), ...)

为什么这么改：check_docs 需要读 SKILL.md 的版本，fixture 必须完整

影响范围：1 处 fixture 补全

方案 4：run_suite 返回码语义修正

修法：有 FAIL/ERROR 就返回 1，只有纯 SKIP（无 FAIL/ERROR）才返回 2

# tests/run_suite.py
# 第 250–252 行
- if report["skipped"]:
-    return 2
- return 0 if report["ok"] else 1
+ if report["failures"] > 0 or report["errors"] > 0:
+    return 1
+ if report["skipped"] > 0:
+    return 2
+ return 0

为什么这么改：FAIL 优先级高于 SKIP，避免 CI 假绿

影响范围：返回码语义，不改测试逻辑

注意：CI 把 2 当通过，修法后 FAIL 会返回 1，CI 会正确报错

方案 5：local_check 编码兜底

修法：加 errors="replace"

# ship-it/scripts/local_check.py
# 第 65 行
- proc = subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8", cwd=str(root))
+ proc = subprocess.run(cmd, capture_output=True, text=True, encoding="utf-8", errors="replace", cwd=str(root))

为什么这么改：解码失败时用 替代，不崩溃

影响范围：1 处参数，不改逻辑

方案 6：check_docs 转义修复

修法：docstring 改为 raw string

# ship-it/scripts/check_docs.py
# 第 242 行
- """解析 spec 文件名中的版本号 v\d+.\d+.\d+，返回 (major, minor, patch) 元组；无则返回 None。"""
+ r"""解析 spec 文件名中的版本号 v\d+.\d+.\d+，返回 (major, minor, patch) 元组；无则返回 None。"""

为什么这么改：raw string 里 \d 是字面量，不告警

影响范围：1 处 docstring，不改逻辑

方案 7：测试残留清理

修法 A（推荐）：测试结束后清理

# tests/test_process_gates.py
# 第 2717 行附近
with temp_repo() as root:
    write_text(root.parent / "outside.md", "# outside\n")
    try:
        # ... 测试逻辑 ...
    finally:
+       (root.parent / "outside.md").unlink(missing_ok=True)

为什么这么改：确保测试结束（无论成功失败）都清理

影响范围：1 处 try/finally

修法 B（备选）：改用临时目录

# 用 tempfile.TemporaryDirectory() 代替 root.parent
# 缺点：改动较大，测试逻辑要调整

为什么不选 B：改动大，没必要

4. 方案推导过程（需求分析员视角）

4.1 需求分析员做了什么

作为需求分析员，我的工作流程是：

  1. 收集问题：从测试输出、CI 日志、用户反馈中收集所有已知问题
  2. 分类归因：把问题按根因分类（路径/版本/语义/编码/转义/残留）
  3. 盘点现有能力：查代码，看既有测试框架、校验脚本、路径约定、版本来源
  4. 推导方案：对每个问题，问"怎么修最合理"，给出推荐方案和备选方案
  5. 评估影响：分析每个方案的影响范围、风险、成本
  6. 做决策：综合所有方案，给出最终推荐

4.2 问题分析与方案推导

问题 1：测试路径硬编码

  • 分析：v5.2.1 把 spec 目录从 docs/specs/ 迁到 ship-it/docs/specs/，但测试代码仍读旧路径。这是迁移遗漏，不是设计。
  • 推导：既然是迁移遗漏，就应该把测试路径也迁过去。改路径字符串是最小改动，不改测试逻辑。
  • 方案：把所有 docs/specs/ 改为 ship-it/docs/specs/（6 处）

问题 2：版本硬编码

  • 分析：测试和 check_docs 硬编码 5.1.0，但 SKILL.md 已是 5.2.1。每次版本升级都要手动改测试，容易遗漏。
  • 推导：版本号的唯一事实源是 SKILL.md frontmatter。如果测试动态读 SKILL.md，就不需要手动同步了。这是"单一事实源"原则。
  • 方案：测试和 check_docs 从 SKILL.md 动态读版本，不再硬编码
  • 备选：手动同步到 5.2.1。为什么不选？治标不治本，下次升级还会漂移。

问题 3：c18 fixture 缺 ship-it/SKILL.md

  • 分析：测试 fixture 只写了根 CHANGELOG.md 和 ship-it/CHANGELOG.md，没写 ship-it/SKILL.md。但 check_docs 改为动态读版本且 fail closed，所以 fixture 必须完整。
  • 推导：fixture 不完整是测试 bug，补全即可。
  • 方案：测试 fixture 里补写 ship-it/SKILL.md（1 行）

问题 4：run_suite 返回码语义错误

  • 分析：run_suite.py:250-252 逻辑是"有 SKIP 就 return 2"，没考虑同时有 FAIL/ERROR 的情况。CI 把 2 当通过，所以有 FAIL 但返回 2 时，CI 假绿。
  • 推导：返回码语义应该是：0 = 全过，1 = 有失败，2 = 有 SKIP 但无失败。FAIL 优先级高于 SKIP。
  • 方案：改为"有 FAIL/ERROR 就返回 1，只有纯 SKIP 才返回 2"

问题 5：local_check 编码崩溃

  • 分析：中文 Windows 下 Python 子进程管道输出默认 cp936，local_check.py:65 用 text=True, encoding="utf-8" 但没加 errors 参数，解码失败时 stdout 为 None，拼接时报 TypeError。
  • 推导：加 errors="replace"，解码失败时用 `` 替代，不崩溃。这是标准的编码兜底做法。
  • 方案：加 errors="replace"（1 处参数）

问题 6：check_docs 转义告警

  • 分析：docstring 里 \d 是无效转义，Python 3.12+ 会告警。这是 Python 语法问题。
  • 推导：改为 raw string（r"""..."""），\d 就是字面量，不告警。
  • 方案：docstring 改为 raw string（1 处）

问题 7：测试残留 outside.md

  • 分析：测试写 root.parent / "outside.md"（仓库根），异常退出时没清理。这是测试清理问题。
  • 推导：用 try/finally 确保测试结束（无论成功失败）都清理。这是标准的测试清理做法。
  • 方案：测试结束后用 try/finally 清理（1 处）
  • 备选：改用临时目录。为什么不选？改动大，没必要。

5. 方案总结

决策树：从三个选项中选择最终方案。

选项：

  • 选项 A：只修本机（.local/ 适配层继续兜底）—— 快但下次 pull 会再漂移
  • 选项 B：修上游源码（tests/ + scripts/）—— 根治问题，贡献回社区
  • 选项 C：两者都做（修上游 + 保留 .local/ 兜底）—— 过度，.local/ 在修完后已无必要

推荐：选项 B（修上游源码）+ 动态读版本 + 提 PR 到 upstream

理由：

  • 上游 7 个问题都是代码层面的不同步，不是环境差异
  • 测试路径硬编码 docs/specs/ 但 v5.2.1 已统一到 ship-it/docs/specs/，这是 bug 不是特性
  • 版本硬编码 5.1.0 但 SKILL.md 已是 5.2.1，这是遗漏不是设计
  • run_suite.py 返回码语义会掩盖 FAIL，这是 CI 假绿的根因
  • 提 PR 可以让本地与上游同步，避免下次 pull 冲突
  • 动态读版本只需改一次，以后自动跟随，不会再次漂移

最终决策：按推荐方案修复 7 个问题

  • 测试路径对齐（6 处）
  • 版本动态读取（2 处）
  • c18 fixture 补全（1 处）
  • run_suite 返回码语义修正
  • local_check 编码兜底
  • check_docs 转义修复
  • 测试残留清理

改动文件：8 个（tests/ 5 个 + scripts/ 3 个）

改动行数：约 20 行（字符串替换 + 逻辑调整）

风险：低（不改契约语义，只修测试与脚本的不同步）
