# v4.7.2 修复后流程图

## 一、谁干什么（角色一览）

```
用户           -> 说签约/验收，点合并按钮
主脑 lead      -> 调度所有人，跟用户说话，但不替用户合并
审查员 auditor3 -> 中间人：所有人把结果给它，它汇总后给主脑；每1分钟巡查大家还活着没
开发 dev-v471   -> 写代码 C1-C14
测试 tester-v471 -> 写测试 + 跑测试 <5分钟
安全 security1  -> 出安全报告
裁判 referee-j1f -> 审 spec、审验收
```

## 二、谁能跟谁说话（通信规则）

```
                    +------+
                    | 用户 |
                    +--+---+
                 签约/验收|  ^ 提醒各一次后不重复
                       v  |
                    +--+---+
                    | 主脑 | <- 只跟审查员说话
                    +--+---+
           派发指令(可直连)|  ^ 汇总报告
                       v  |
                    +--+---------------+
                    | 审查员 auditor3   | <- 所有人把结果给它
                    | (每1分钟巡查)     |    它汇总后给主脑
                    +--+--+--+--+---+
              报告 v   v  v  v
            +----+ +----+ +----+ +----+
            |开发| |测试| |安全| |裁判|
            +----+ +----+ +----+ +----+
```

规则：
- 主脑派人干活 -> 可以直接找人（派发可直连）
- 大家交结果 -> 必须交给审查员，审查员汇总后给主脑（不许直接给主脑）
- 审查员每1分钟巡查 -> 正常不出声，发现谁挂了才喊主脑

## 三、整个流程怎么走（5步）

```
第1步  签约前（安安静静）
  需求 -> 写契约草稿 -> 裁判审 -> 用户说签约
  * 此时审查员不干活（心跳暂停）
  * 主脑不催用户

         +----------------------------------+
第1步   | 需求 -> 契约草稿 -> 裁判审 -> 签约 |  心跳暂停 不催用户
         +----------------+-----------------+
                        v 用户签约
         +----------------------------------+
第2步   | 审查员先上岗 -> 三份开工报告 -> 闸门|  审查员必须先于开发/测试
         +----------------+-----------------+
                        v 闸门通过
         +----------------------------------+
第3步   | 审查员在岗后 -> 才派开发+测试干活  |  结果交给审查员不交主脑
         +----------------+-----------------+
                        v 报告汇总
         +----------------------------------+
第4步   | 四道闸门 + 测试<5min -> 裁判验收    |  任一不过就回去改
         +----------------+-----------------+
                        v 裁判通过
         +----------------------------------+
第5步   | 用户验收 -> 清理 -> 版本号 -> 交付  |  主脑不合并 用户自己合
         +----------------------------------+
```

## 四、为什么以前老出错（对比）

```
以前(v4.7.0/v4.7.1)：              现在(v4.7.2 修复后)：
  审查员经常迟到                     审查员必须先上岗(第2步)
  主脑先派开发再叫审查员             审查员没上岗不准派开发(C12)
  审查员跑完就消失了                 每1分钟心跳巡查(C12)
  开发直接把结果给主脑               结果必须经审查员汇总(C12)
  开了23个重复的智能体               复用优先，新开要写理由(C13)
  主脑反复催请签约                   提醒一次后不再催(C14)
  心跳正常也骚扰用户                 正常静默，异常才通知(C14)
```
