## 1. 背景与目标（what & why）

ship-it skill 在实际使用中暴露两类"同源共错"漏洞：

1. **能力幻觉**：团队模式测试员（或主脑）在 Step 4 验收截图环节，明明分配的模型支持图片输入，却凭记忆/印象声称"不支持"直接降级，跳过实测。team-mode.md 有"首次组队探针"但无"声称不支持前必须实测"的硬约束——角色卡缺这道防线。
2. **契约逃逸**：agent 既是执行者又自判合规，可滥用 mini-spec 快速通道、滥用纯文档免流程、跳过需求澄清、测试从代码派生或核销表自填✅——SKILL.md 有各门槛但无"禁止自证"总原则，缺一道兜底防线。

改完：测试员角色卡加"实测为证"硬约束；SKILL.md 加"禁止自证"原则 + 反偷懒红线清单 + mini-spec/纯文档免流程"资格不可自判"约束。直击根因，最小改动，不扩展 check_spec.py。

### 需求澄清记录（Step 1 产出，签约时展示给用户确认）

- **原始需求**：用户反映"跟工具对话发现开发过程中验收截图环节明明是支持图片输入的模型竟然说不支持，明显很严重的幻觉，应该有角色卡才对啊"；"有的时候智能体绕过契约进行偷懒应该怎么避免"
- **优化后需求**：针对 ship-it skill 的两类漏洞——(1) 图片输入能力幻觉：在 team-mode.md 测试员角色卡加"声称不支持图片输入前必须先发一张探针图实测，只有实测失败才能降级"硬约束；(2) 契约逃逸：在 SKILL.md 加"禁止自证：agent 不可自判合规，关键节点必须机器可查或用户确认"原则 + 覆盖四种偷懒场景的红线清单 + mini-spec/纯文档免流程"资格不可自判"约束
- **优化说明**：补了联网搜索（业界"evidence-first / trust but verify"共识印证方向）；把"应该有角色卡"明确为"测试员角色卡加硬约束"；把"绕过契约偷懒"拆成四种具体场景并对应到 SKILL.md 现有结构
- **用户问答**：
  - 图片幻觉修复力度？→ 用户选"角色卡加硬约束"（最小直击根因）
  - 遇过哪些偷懒场景？→ 用户全选四种：滥用 mini-spec / 滥用纯文档免流程 / 跳过需求澄清 / 测试从代码派生或核销表自填✅
  - 防绕过修复力度？→ 用户选"红线清单 + 禁止自证原则"（不扩展机器校验）

## 5. 契约条款（C1 / C2 / …）

### C1 测试员声称图片不支持前必须实测

- **前置条件**：团队模式，测试员角色被分配，需图像输入能力；或主脑在无测试员时兼任截图认证
- **后置条件**：`team-mode.md` 测试员角色卡含硬约束语句——"声称不支持图片输入前必须先发一张探针图实测，只有实测失败才能降级"；实测结果（成功/失败）写入测试报告
- **失败行为**：凭记忆/印象直接说"不支持"就降级 = 违规；降级决定必须附实测失败证据（哪张图、什么报错）
- **不变式**：任何"降级为主脑核验"的决定必须附实测失败证据；无证据 = 不可降级 🔒

### C2 关键原则新增"禁止自证"

- **前置条件**：`SKILL.md` 关键原则节（当前 9 条）
- **后置条件**：关键原则新增第 10 条"禁止自证：agent 不可自判合规，关键节点（mini-spec 资格 / 纯文档免流程资格 / 核销✅ / 能力声明）必须机器可查或用户确认"
- **失败行为**：agent 在上述关键节点自判合规 = 违规
- **不变式**：执行者 ≠ 裁定者；agent 可执行但不可自判通过 🔒

### C3 反偷懒红线清单覆盖四种场景

- **前置条件**：`SKILL.md` 常见坑表或关键原则节
- **后置条件**：含四种偷懒场景及其对策——(1) 滥用 mini-spec 快速通道 (2) 滥用纯文档免流程 (3) 跳过需求澄清 (4) 测试从代码派生或核销表自填✅
- **失败行为**：缺任一场景 = 未覆盖
- **不变式**：每种场景都有"不可自判"约束；清单可被 agent 在开工前逐条自检

### C4 mini-spec 资格不可自判

- **前置条件**：`SKILL.md` mini-spec 快速通道节（第 185-201 行）
- **后置条件**：mini-spec 三条门槛加约束——"agent 不可自行裁定走 mini-spec；改动文件数/接口/表/权限/外部输入任一不符 = 必须完整 spec；疑义时走完整 spec 或问用户"
- **失败行为**：agent 自判走 mini-spec 但实际多文件/改接口/动表/动权限/有外部输入 = 违规
- **不变式**：mini-spec 是例外不是默认；门槛由客观事实（文件数/接口签名/表结构）判定，不由 agent 主观判断

### C5 纯文档免流程资格不可自判（尤其涉及流程规则本身）

- **前置条件**：`SKILL.md` 纯文档免流程节（第 203 行）
- **后置条件**：纯文档免流程加约束——"agent 不可自判'纯文档'；改动涉及流程规则/skill 本身/agent 行为约束时不可免流程，必须走完整 spec"
- **失败行为**：改流程规则却自判免流程 = 违规（本次改动本身即范例：改 skill 规则走了完整 spec）
- **不变式**：改规则者受规则约束 🔒

### C6 版本号与 CHANGELOG 同步

- **前置条件**：`SKILL.md` frontmatter version = 4.0.0；`ship-it/CHANGELOG.md` 顶部为 4.0.0
- **后置条件**：frontmatter version → 4.1.0（新功能 = minor）；CHANGELOG 顶部新增 4.1.0 记录，含本次改动摘要
- **失败行为**：版本号两处打架 / CHANGELOG 缺记录
- **不变式**：版本号唯一来源 = frontmatter，CHANGELOG 与之一致
