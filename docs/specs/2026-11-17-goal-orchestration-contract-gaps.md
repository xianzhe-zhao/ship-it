## 1. 背景与目标（what & why）

**现状**：v4.4.0（PR #6）上线「目标驱动编排」后，**自举实跑暴露两处契约空白**，两者都属"只有名字、没有规则"：

1. **`paused` 无迁移条件**：`team-mode.md` 把 `paused` 列为合法叶子状态、v4.4.0 spec 的 C2 同样允许，但状态机只定义了 `pending → active → done` 与 `active → blocked → active`，**全文无一处说明何时进入 / 何时退出 paused**。后果：agent 可把卡住的叶子标成 `paused`——它既不算"未完成"也不算"卡住"，Step 5 核销时可能被写成"无未完成叶子"，形成**绕过核销**的缝（与「禁止自证」冲突）。
2. **"连续 3 轮"的"轮"未定义**：v4.4.0 spec C6 规定"同一阻塞连续 3 轮未解除 → 目标置 `blocked`"，但"轮"没有计数单位；四处引用（`ship-it/SKILL.md`、`references/team-mode.md`、spec C6、spec §8②）全部悬空。后果：同一情形两人可得出不同结论，`blocked` 判定不可复现。

**为什么要改**：v4.4.0 引入的机器校验（目标树行、blocked 条件）依赖这两处语义；不补则仍留主观解释空间。

**改完是什么样**：`paused` 成为有明确进入条件、必填信息、恢复路径的**短期暂停**，且**核销前必须清零**；"连续 3 轮"明确为**目标自动续轮**（可机器读取的 `roundsStarted`）；两处定义同步进 `SKILL.md` 与 `team-mode.md`；版本 **4.4.1**。

## 5. 契约条款（C1 / C2 / …）

### C1 `paused` 仅用于"等外部输入的短期暂停"

- **前置条件**：叶子当前为 `active`，且因**外部输入**无法推进（等用户决策 / 等第三方响应 / 等资源）。
- **后置条件**：置 `paused` 时**必须同时写 note**，含两项非空内容——**暂停原因**与**恢复条件**；`paused` 叶子的完成计数不变（不计入 done）。
- **失败行为**：原因或恢复条件缺失 → **不得置 paused**，应保持 `active` 或置 `blocked`（二者择一，按"是否真的卡住"判断）。
- **不变式**：`paused` 不得用于"以后再说 / 暂缓实现 / 优先级降低"——那两类分别属于 `retired`（不做，需理由）与 `blocked`（卡住）。

### C2 `paused` 恢复与核销前清零（防绕过核销）

- **前置条件**：`paused` 叶子的恢复条件已满足，或进入 Step 5 契约核销。
- **后置条件**：恢复条件满足后置回 `active`（或直接 `done`）；**Step 5 核销时，Step 1–5 分组内 `paused` 叶子数必须为 0**。
- **失败行为**：核销时仍有 `paused` 叶子 → **核销不合格**（与 C5「未完成叶子」同等处理），不得进入 Step 6；须恢复该叶子或显式 `retired` 并说明理由。
- **不变式**：`paused` **不计入完成**，也**不得被解释为"不阻塞"**；它与 `pending`/`active`/`blocked` 一样属于"未完成"。

### C3 "连续 3 轮"= 目标自动续轮

- **前置条件**：目标处于 `active`，且同一阻塞条件持续存在。
- **后置条件**：以 `get_goal` 返回的 **`roundsStarted`（自动续轮计数）**为准——同一阻塞在 **3 个自动续轮**内未解除，才允许 `update_goal` 置 `blocked`；置 `blocked` 时必须写明具体阻塞条件。
- **失败行为**：宿主不提供自动续轮计数（其他环境）→ 降级为"主脑在每轮汇报中显式记录同一阻塞的出现次数"，并在汇报中注明"轮次口径降级"；**未达阈值不得置 blocked**，保持 `active`。
- **不变式**：不得以"困难 / 不确定"为由置 `blocked`；**不得**用汇报次数或重试次数替代自动续轮计数（那是另外两种口径，已排除）。

### C4 两文件单一口径 + 9 步语义不变

- **前置条件**：任何对 `ship-it/SKILL.md` 或 `ship-it/references/team-mode.md` 的流程规则改动。
- **后置条件**：`paused` 语义（C1/C2）与"3 轮"口径（C3）在两文件表述**一致**，且与 spec C1–C3 一致；9 步流程、闸门、核销、用户验收语义保持不变。
- **失败行为**：两文件出现同一规则的两种说法 → 视为不合格，须统一后再进入测试；若改动触及步骤语义（增删步骤 / 放宽闸门 / 弱化验收）→ 必须按 major 递增并标注 ⚠️，不得以 patch 发布。
- **不变式**：`SKILL.md` 与 `team-mode.md` 不出现相互矛盾的表述（同一规则只允许一种口径）。

### C5 版本与变更记录三处一致

- **前置条件**：改动进入交付（Step 7）。
- **后置条件**：`ship-it/SKILL.md` frontmatter `version`、`ship-it/CHANGELOG.md`、仓库根 `CHANGELOG.md` 三处均为 **4.4.1**，且两处 CHANGELOG 均记录本次两处补口（paused 语义 + 轮次口径）。

## 7. 边界与异常

| 场景 | 期望表现 |
|---|---|
| `paused` 长期不恢复 | 不得无限 paused：超过一个阶段（如跨 Step）仍无法恢复 → 转 `blocked`（写明条件）或 `retired`（写明理由） |
| 核销时 `paused` > 0 | 核销不合格，退回恢复或 retired（C2） |
| `paused` 出现在 Step 6–9 分组 | 不纳入核销分母（C5 口径），但 Step 9 收尾时必须为 0 |
| 同一阻塞反复出现但未达 3 个自动续轮 | 保持 `active`，不得提前置 `blocked`（C3） |
| 宿主无自动续轮计数（其他环境） | 降级为文字计数并注明"轮次口径降级"，不阻塞流程（C3 失败行为） |
| 用户未回答 paused / 轮次口径 | 不擅自选默认值，停下来问（本次已问并获答） |
| 两文件口径不一致 | 视为不合格，统一后再测（C4） |
