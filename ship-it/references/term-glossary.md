# 流程术语词典（权威）

> 本文件是 ship-it 流程术语的唯一权威来源，check_terms.py 读取本校验（v5.2.1 / C5 新建）。
> 改流程术语必须先改本词典，再改正文；历史 CHANGELOG/历史 spec 中的旧名走 allowlist 保留。

## 权威流程术语

| 术语 | 别名（应统一的非权威写法） | 一句话定义 |
|---|---|---|
| 5 轨道 | 五轨道、五选一、五条轨道 | spec「变更类型」节的五种变更轨道：feature/bug/perf/framework/refactor（+spike 特殊态） |
| 咨询顾问模式 |  | 性能工程师/代码安全员的协作模式：诊断+出有依据方案，交主脑裁定，不代写代码不裁定（"顾问模式"是子串非真分歧，不列为别名） |
| 代码安全员 | 代码审查员 | 团队模式角色：负责代码安全审查（应以代码安全员为准） |
| 监察员 | 审查员 | 团队模式角色：负责流程合规巡逻（应以监察员为准） |
| 需求分析师 | 需求澄清员 | 团队模式角色：负责需求澄清与分析（应以需求分析师为准） |

## allowlist（历史文件旧术语允许保留）

以下文件中的旧术语/别名允许保留，check_terms.py 不判 FAIL：

- ship-it/CHANGELOG.md（历史版本记录）
- CHANGELOG.md（根，历史版本记录）
- ship-it/docs/specs/*.md（历史 spec，历史真相档案）
- docs/specs/*.md（历史 spec，过渡期双保留）

## 改名纪律

- 改流程术语必须先改本词典的术语列和别名列。
- 新增术语先加到本词典，再在正文使用。
- 别名是"应统一的非权威写法"（如"五轨道"应统一为"5 轨道"），正文应用权威术语；check_terms.py 扫正文发现别名会报 FAIL。
- 只收录真正该被统一的别名。合理同义词/展开形式（如"叶子代理工具隔离"是 leaf-guard 的中文释义、"分轮"是"分轮追问"的简称）不列为别名，避免正文全量误报。日常通用词（spec/draft/verify/accept 等）更是流程基础设施词汇，绝不列为别名。
