# 写作铁律（rule-style.md）

> 结论前置：本文件定义 8 条写作铁律、1 份硬禁用词清单和正反例，供 SKILL.md / README / spec 模板 / spec / 审查报告共用。
> 机器读取：check_spec.py 只从下方 hard-forbidden 代码块读取词表；扫描 spec 时跳过代码块与行内代码。
> 判定归属：词表与长度由 check_spec.py 机器判定；规范性“建议 / 可以”与语义强弱由裁判员判定。

## 适用范围

- 适用对象：SKILL.md、README.md、spec 模板、spec 契约、审查报告。
- 用法：写作时逐条对照 8 条铁律；交付前跑 check_spec.py；裁判员按本文件复核。

## 8 条写作铁律

### 1. 结论前置
- 铁律：每段第一句写结论，理由与细节放后面。
- 判定：删掉第一句后段落失去主旨 = 违规；段落以“由于 / 因为 / 随着 / 为了”开头 = 违规。
- 反例：`由于历史上多次漏测，所以本流程要求每条条款都有用例。`
- 正例：`每条条款必须有对应用例；历史漏测是这条规则的来源。`

### 2. 一条一句
- 铁律：一条规则只写一个可判定的要求；复合要求拆成多条。
- 判定：一句话里出现两个以上“必须 / 禁止”且作用对象不同 = 违规。
- 反例：`必须补测试并更新文档且通知用户。`
- 正例：`必须补测试。` `必须更新文档。` `必须通知用户。`

### 3. 禁模糊词
- 铁律：规范性文本禁止使用硬禁用词清单中的词；用确定动作或阈值替代。
- 判定：check_spec.py 扫描 spec 命中词表 = FAIL；代码块与行内代码中的词表引用不算。
- 反例：`必要时补充测试。`
- 正例：`覆盖率低于 80% 时必须补测试。`

### 4. 每条有判定方式
- 铁律：每条规则必须写明机器命令 + 退出码，或写明人工判定清单。
- 判定：规则段落没有“判定 / 验证 / 退出码 / 用例名 / 判定清单”之一 = 违规。
- 反例：`测试要充分。`
- 正例：`运行 python -m unittest tests.test_process_gates；退出码 0 = 通过。`

### 5. 冲突取严
- 铁律：两条规则冲突时执行更严格的一条，并把裁定写进 spec 的冲突表。
- 判定：同一场景出现两种处理方式且未写明取严 = 违规。
- 反例：`旧版允许“没问题”算验收，新版只认“验收”。`
- 正例：`旧版“没问题”算验收的规则废止；只认严格“验收”。`

### 6. 重要前置
- 铁律：阻断性内容放在文件或章节开头，背景与展开放后面。
- 判定：红线 / 闸门 / 禁止项出现在第三节之后 = 违规。
- 反例：`先讲三十行历史，最后一段写“禁止 AI 合并 PR”。`
- 正例：`开头写“禁止 AI 合并 PR”，历史放附录。`

### 7. 删废话不删语义
- 铁律：删铺垫、重复、口号；前置 / 后置 / 失败 / 不变式 / 例外 / 边界必须保留。
- 判定：删句后出现无法判定的行为 = 违规；条款缺少四要素 = check_spec.py FAIL。
- 反例：`本流程经过长期实践，大家一致认为要重视测试。`
- 正例：`每条条款必须有对应用例；缺用例 = FAIL。`

### 8. 术语固定
- 铁律：同一概念全文只用一个词，首次出现给出定义。
- 判定：同一概念出现两种叫法 = 违规。
- 术语表：

| 固定术语 | 含义 | 禁止混用 |
|---|---|---|
| 签约 | 用户消息严格等于“签约”两个字 | 确认 / 同意 / 通过 |
| 验收 | 用户消息严格等于“验收”两个字 | 没问题 / 发吧 |
| 闸门 | 机器判定且非零退出即阻断的检查 | 提醒 / 建议 |
| 条款 | spec 第 5 节的 C1..Cn | 需求点 |
| 验收项 | spec 第 6 节的 A1..An | 检查项 |
| 核销 | spec 第 9 节“条款→用例→结果→路径真实性” | 对账 |

## 判定与替换

- 判定：规范性文本命中任一词 = FAIL；引用词表本身时放进代码块或行内代码。
- 替换：写成确定动作（必须 / 只能 / 禁止 / 固定为）或给出阈值。
- 机器读取：check_spec.py 读取 BEGIN / END 之间的词表，扫描 spec 时跳过代码块与行内代码。
- 规范性“建议/可以”由裁判员判定；`建议使用 X` = FAIL，`必须使用 X` = PASS；`才可以` 等强制短语豁免。

## 正反例对照

| 场景 | 反例 | 正例 | 判定 |
|---|---|---|---|
| 结论位置 | 先写三段背景再写要求 | 第一句写要求 | 删首句后失去主旨 = 违规 |
| 规则粒度 | 一条写三个动作 | 一条一个动作 | 两个以上动作 = 违规 |
| 模糊表述 | `尽量覆盖异常路径` | `异常路径覆盖率 100%` | 命中词表 = FAIL |
| 可判定性 | `做得稳一点` | `退出码 0 = 通过` | 无判定方式 = 违规 |
| 冲突处理 | 两套口径并存 | 取严并记录裁定 | 未取严 = 违规 |
| 信息顺序 | 禁止项放文末 | 禁止项放开头 | 禁止项在第三节后 = 违规 |
| 精简 | 删掉失败行为 | 只删铺垫 | 缺四要素 = FAIL |
| 术语 | 同一概念两种叫法 | 术语表固定 | 混用 = 违规 |

## 自检

- 本文件遵循自身铁律：结论前置、一条一句、无硬禁用词（词表本身在代码块内）、每条有判定方式、术语固定。
- 机器检查：check_spec.py 读取本文件词表并扫描 spec；本文件不含词表外的模糊词。
