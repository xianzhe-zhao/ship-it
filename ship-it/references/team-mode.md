# 团队模式（主脑 + 角色化多智能体协作）

> 本文件是团队模式执行形态的细节。9 步流程、闸门、契约模式（spec-first / 条款派生测试 / 核销 / 用户验收）**全部不变**；
> 团队模式只改变"谁来执行"：同样的 9 步，由"主脑 + 角色"执行。
> **本 skill 不硬编码任何具体模型名或模型特有数值限制**——模型信息一律来自项目 runbook 的「模型能力清单」（见下）。

## 何时使用（主脑自动判断）

用户提出需求时，主脑按三条判断（满足任一 → 启用团队模式）：

1. 需求涉及多文件（前后端都有，或多个模块）
2. 全栈（前端 + 后端都动）
3. 用户明确要求团队模式

三条都不满足，或需求符合 mini-spec 快速通道 → 主脑单干。
判断结果 + 理由写进 spec「方案自审」节。
用户明确说"不用组队 / 你自己做" → 主脑单干，即使需求大。

## 角色能力要求表

| 角色 | 能力要求 | 形态 |
|---|---|---|
| 主脑 | 会话模型（固定） | 会话本身 |
| 需求澄清员 | 联网搜索能力 | subagent（一次性） |
| 后端开发 | 大上下文优先 | subagent |
| 前端开发 | 无特殊要求 | subagent |
| 代码审查员 | 大上下文优先 | subagent（每轮派发一次） |
| 测试员 | **必须图像输入** | 持久 teammate（失败降级 subagent） |
| 改动说明员 | 无特殊要求 | subagent |

- "大上下文优先"是软要求：模型列表未声明上下文大小时，不影响分配。
- "必须图像输入"是硬要求：分配给测试员的模型必须经探针验证支持图像输入；无模型满足 → 截图认证降级为主脑亲自核验，或经用户同意跳过并注明。

## 模型发现流程（首次做一次）

首次使用团队模式（项目 runbook 无「模型能力清单」节）时：

1. **拉模型列表**：优先用宿主的模型列表工具（若提供）；DSH 当前无专用模型列表工具时**读设置文件** `~/.dsh/settings.yaml`（`agent-default-model` 给默认路由，`llm-pi-ai.providers.<id>.models` 给模型池与上下文窗口）；其他环境用 provider 的模型列表接口。
2. **联网核实能力定位**：对主脑不熟悉的模型（新发布 / 新命名），**联网搜索官方文档 / 发布页**确认"擅长定位 + 输入模态"（如编程特化、多模态视觉、长推理），写入注册表「备注」列——**不许凭记忆猜新模型能力**；查不到官方信息 → 按"无特殊能力"处理，不分配有硬要求的角色（如测试员）。
3. **实测探针**（仅对列表/官方文档未确认的能力，如图像输入在本环境是否透传）：向候选模型发一张小测试图（如 64×64 PNG），记录成功/失败。成本小，只做一次。
4. **记录注册表**：写入项目 `docs/deploy-runbook.md` 的「模型能力清单」节（模板见下）。
5. **分配角色**：角色 → 模型按能力匹配，用户明确偏好优先；分配结果 + 理由写进 spec「方案自审」节，并**作为配置记入项目 runbook「角色分配」表**——模型名只存在于配置（runbook），禁止写死在 skill 正文或代码里。

**复核触发**（不为每个需求重复拉取；触发后 = 增量扫描 + 重分配 + 写回 runbook 配置）：

- 用户更新模型配置（列表出现新模型 / 移除 / 改名）→ **对新模型联网核实能力定位**（禁止凭记忆猜）
- **会话实际路由出现注册表未记录的模型名**（配置文件滞后于实际路由，以实际为准）→ 同上
- 用户报告能力异常（如某模型图像输入突然报错）
- 复核是增量的：只对变动模型做能力搜索 + 探针；重分配结果写回项目 runbook「角色分配」表，下次组队生效。

**离线回退**：拉取模型列表失败 → 用最近注册表并注明"能力信息可能过期"；无注册表 → 全部角色回退会话模型，注明，联网后补建。

### 注册表模板（记入项目 `docs/deploy-runbook.md`）

```markdown
## 模型能力清单（环境级信息；同机新项目直接复制本节约定，不重复拉取）

> 最近更新：YYYY-MM-DD（拉列表 + 联网核实能力 + 探针）

| 模型 ID | 上下文大小 | 图像输入 | 单次请求图片上限 | 备注 |
|---|---|---|---|---|
| <provider/model> | <已知则记，否则"未知"> | ✅/❌（官方声明 + 本环境探针结果） | <已知则记，否则"未知"> | <擅长定位（联网核实官方文档）：如"编程特化 / 多模态视觉 / 长时序推理 / 轻快性价比"> |

角色分配（本环境）：后端开发 = <模型>；前端开发 = <模型>；审查员 = <模型>；测试员 = <模型>；改动说明员 = <模型>
```

## 角色卡

### 主脑（会话本身）
- **职责**：spec 唯一 owner；定角色集与模型分配；统一派发所有 subagent；持有跨轮状态；唯一对用户交付的成员；契约把控（spec-first / 核销 / 验收闸门）
- **输入**：用户需求、spec、各角色产出
- **输出**：spec（含方案自审：角色集 + 形态 + 分配模型 + 理由）、每步汇报（可附 ≤2 条流程优化建议）、最终交付
- **能力要求**：会话模型，固定
- **形态**：会话本身（不 spawn）
- **闸门**：不向任何角色让渡契约权；不跳步

### 需求澄清员
- **职责**：Step 1 需求澄清——联网搜索需求相关技术/方案、识别歧义点、输出优化后需求 + 澄清记录 + 待问用户的问题清单
- **输入**：用户原始需求、代码库现状线索（主脑提供）
- **输出**：优化后需求描述 + 优化说明 + 待问用户的问题清单（主脑审核后转达用户）
- **能力要求**：联网搜索能力
- **形态**：subagent（一次性，主脑统一派发）
- **闸门**：不直接面对用户；输出经主脑审核；主脑用 `ask_user_question` 转达问题、拿答案

### 后端开发
- **职责**：后端代码改动（接口 / 数据 / 逻辑）
- **输入**：spec 相关条款、文件作用域、自检要求
- **输出**：代码 diff + 自检结果（语法 / 测试 / 门禁）
- **能力要求**：大上下文优先
- **形态**：subagent（一次性，按任务派发）
- **闸门**：产出可追溯到条款；自检通过才提交

### 前端开发
- **职责**：前端代码改动（页面 / 组件 / 样式）
- **输入**：同后端开发
- **输出**：代码 diff + 自检结果（UI 改动含坐标断言要求）
- **能力要求**：无特殊要求
- **形态**：subagent
- **闸门**：同后端开发

### 代码审查员
- **职责**：测试前四项审查：安全增量（新增依赖 / 新外部输入面）、废代码、重复功能、注释审核（语言 / 准确性 / 与代码一致）
- **输入**：本轮 diff + spec 相关条款；第 2 轮必含第 1 轮问题清单与修复说明
- **输出**：结构化报告（文件 / 行 / 严重度 / 建议）
- **能力要求**：大上下文优先
- **形态**：subagent（每轮派发一次；跨轮状态由主脑持有）
- **闸门**：审查不可跳过；高危问题 → 打回对应开发角色，修复后复审，最多 2 轮；仍不过 → 主脑报用户决策

### 测试员
- **职责**：Step 4 两支柱：契约派生用例（每条 C 条款 ≥1，用例名带条款号）+ 分级回归；截图认证
- **输入**：spec 条款、回归范围（runbook 核心功能清单）、测试环境地址
- **输出**：测试报告（用例清单 + 结果 + 报告路径）、截图认证结论
- **能力要求**：**必须图像输入**
- **形态**：持久 teammate（多轮记忆；创建失败降级 subagent）
- **闸门**：测试只读、只打测试环境；不写业务数据、不发付费请求；FAIL>0 → 打回对应开发角色，修复后重测，最多 2 轮
- **实测为证（防能力幻觉）**：声称"不支持图片输入"前**必须先发一张探针图实测**（如 64×64 PNG），只有实测失败才能降级；凭记忆/印象直接说"不支持"就降级 = 违规。降级决定必须附实测失败证据（哪张图、什么报错），写入测试报告。无证据 = 不可降级 🔒

### 改动说明员
- **职责**：测试通过后起草五项报告：重点变更 / 验收标准清单 / 测试步骤与预期 / 回滚方式 / 明确请求
- **输入**：spec、核销表、测试报告、版本号
- **输出**：报告草稿（主脑审核后交付用户）
- **能力要求**：无特殊要求
- **形态**：subagent
- **闸门**：缺五项中任一项 → 退回补全（限 1 轮）；不直接面对用户

## 派发协议

### subagent prompt 模板（所有一次性角色统一格式）

```
你是 ship-it 团队模式中的<角色名>。
## 上下文
- 项目：<项目路径>
- spec：<spec 路径>（相关条款：C<n>…）
- 文件作用域：<本次任务允许改动的文件清单>
## 任务
<具体任务，引用条款号>
## 自检要求
- 语法 / 现有测试 / 项目门禁必须通过
- <角色特定项：如审查员四项清单 / 测试员两支柱用例集>
## 输出格式
<结构化输出，如报告模板>
```

### 派发规则

- **主脑统一派发所有 subagent**（不假设 teammate 有 subagent 派发能力；teammate 缺工具时由主脑代派）
- prompt 必含：spec 条款号 + 文件作用域 + 自检要求（缺一 = 派发不合格）
- 跨轮状态（审查第 2 轮、修复后重测）由主脑持有，写入下一次 prompt

### 截图协议（测试员）

- 读图分批；**批量大小 = 注册表记录的测试员分配模型的单次请求图片上限**（用户全局指令有更严限制时从严）
- 优先关键页面（核心路由、本次改动页面），不逐页截图
- 坐标断言用数值（与 Step 3 UI 视觉自测一致）

## 协调原语与实时查看

### 能力要求（平台无关，向下兼容）

团队模式只要求宿主环境提供下列能力（**任何实现均可**；角色卡、闸门、契约模式不变，按能力映射即可）：

| # | 能力 | 用途 | 缺失时回退 |
|---|---|---|---|
| 1 | 创建持久 teammate（命名、多轮记忆、同会话可复用） | 测试员 | 降级为 subagent |
| 2 | 一次性 subagent（每次调用可选模型） | 审查员 / 改动说明员 / 开发角色 | 主脑亲自做 |
| 3 | 消息传递（teammate ↔ 主脑） | 星型协调 | 必需项——缺失则不启用团队模式 |
| 4 | 共享任务看板（依赖 + 文件写入范围） | ≥2 个 teammate 并行防踩文件 | 主脑持有依赖表（spec 仍是契约层） |
| 5 | 等待 / 打断（等状态变化不轮询；打断跑偏 teammate） | 调度 | 等自然结束后重派 |

### DSH 映射（本环境适配）

| 能力 | DSH 工具 |
|---|---|
| 创建持久 teammate | `spawn_teammate`（**继承主脑会话模型**，无模型参数；实测：主脑切换会话模型后，新 teammate 跟随主脑） |
| 一次性 subagent（默认路由） | `subagent` / `subagent_fork`（无模型参数）；`subagent_claude_code` / `subagent_codex`（切换 CLI 后端） |
| 一次性 subagent（**指定模型**） | `workflow` 的 `agent(prompt, { provider, model })` —— 按调用指定模型的入口（适合批量编排） |
| 消息传递 | `send_message` / `list_agents` |
| 共享任务看板 | `team_task_create` / `team_task_list` / `team_task_update` |
| 等待 / 打断 | `wait_agent` / `interrupt_agent` |
| 模型列表 | 无专用工具 → 读 `~/.dsh/settings.yaml`（`agent-default-model` + `llm-pi-ai.providers.*.models`），快照记入项目 runbook |

其他支持多智能体的环境（Claude Code / Codex 等）：按上表能力列映射到对应原语；无共享看板时由主脑在 spec「方案自审」节持有依赖表。

### 使用规则

- **共享看板**：≥2 个持久 teammate 并行时，用看板声明依赖（blocked_by）+ 文件写入范围（write_scopes）防互相踩文件；看板是操作层，spec 是契约层
- **作用域不相交**：并行角色的文件作用域必须不相交；相交则串行
- **teammate 复用**：同一会话内复用同一 teammate，不逐任务重建
- **等待**：主脑用等待原语等状态变化，不轮询
- **打断**：teammate 跑偏 / 卡住 → 打断重派（见失败处理表）

### 实时查看（DSH Web GUI）

- 会话头部**「智能体团队」按钮**（双人图标）→ 面板：**成员**（实时状态：运行中 / 未运行 / 准备中 / 失败 + 模型）+ **任务**（只读看板）
- **点击成员行 = 打开成员会话**：在主视图打开该 teammate 自己的对话框，实时看它干活，也可直接给它发消息
- 一次性 subagent 不进成员列表：进度在主会话显示为后台任务通知，最终报告交主脑

## 失败处理与降级

| 失败 | 处理 |
|---|---|
| 模型不可用（网关故障 / 模型下线） | 回退会话模型完成任务，汇报注明"模型回退"，不阻塞流程 |
| 审查员 / 改动说明员 subagent 派发失败或超时 | 主脑亲自做同样工作并注明 |
| 测试员 teammate 创建失败（provisioning / failed） | 降级为 subagent（分配给测试员的模型）执行同样测试工作，注明 |
| teammate 缺工具（无终端 / 无读图） | 该角色工作改由主脑派发的 subagent 完成 |
| teammate 跑偏 / 卡住 | 主脑打断（DSH：`interrupt_agent`）重派；环境无打断能力 → 等自然结束后重派 |
| 无支持图像输入的模型 | 截图认证降级为主脑亲自核验（宿主主脑自带读图能力时直接用它），或经用户同意跳过并注明 |
| 凭记忆/印象声称"不支持图片输入"（未实测） | **违规**——必须先发探针图实测；只有实测失败才能降级，降级决定附失败证据（哪张图、什么报错）写入测试报告 |
| 审查 / 测试打回超 2 轮 | 停止循环，报用户决策，不带病推进 |
| 角色产出无法追溯到条款 | 主脑退回重做 |

## 契约把控与流程优化建议

- 主脑是 spec 唯一 owner；各角色产出（代码 / 审查报告 / 测试报告 / 改动说明）必须可追溯到 spec 条款
- 主脑每步向用户汇报时可附 ≤2 条"流程优化建议"（含理由与采纳成本）
- 被采纳的建议记入项目 runbook 或本 skill 的 CHANGELOG
