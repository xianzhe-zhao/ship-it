# 2026-11-20 v4.7.2 遗留问题修复

## 1. 背景与目标

v4.7.1 验收后新发现 P2/P3 与 reviewer 派发、Step 9 清理问题；本次修复。gzip/解压与远端 main 合并不在本 spec。

## 2. 需求澄清记录

- 用户要求：除 gzip 压缩/解压外，其他问题都修复；当成新需求；按最新 ship-it 走完整流程。
- 交付仍由用户处理：test 分支/本地 main；主脑不合并、不推 main。

## 3. 方案自审与技术蓝图

- 修改 `ship-it/scripts/run_suite.py`、`check_roles.py`、`check_text.py`、`pre_commit_check.py`、`guard_large_write.py`、`.github/workflows/ship-it-gates.yml`、`ship-it/SKILL.md`/`team-mode.md`。
- 新增/更新对应测试；版本 4.7.2；CHANGELOG/README 三处同步。
- C12 落地：`schedule_create` 建每 1 分钟 reviewer 心跳（this_session 会话态，唤醒 auditor3 巡检 + 写 patrol/last_active_at；机器证据为 patrol 轮次时间戳，非仓库内文件）+ `check_roles` 机器闸门校验顺序/间隔/汇总，双重保障 reviewer 常驻在岗。
- 心跳时机（优化）：`schedule_create` 的 reminder 会投递到 session、用户可见，无法真正静默；故心跳仅在 dev/tester 活跃期间启用，工作间隙（等用户签约、等审查产物、等裁定）必须 `schedule_edit active:false` 暂停，避免无意义巡检打扰用户。主脑在每个 checkpoint 主动暂停/恢复心跳，而非一直跑。签约前暂停；dev/tester 派发后恢复；dev/tester 停止后暂停。
- C13 实例 roster（运行时会话态，非仓库产物）：lead / reviewer(auditor3) / dev(dev-v471) / tester(tester-v471) / security(security1) / referee(referee-j1f)；具体名字随会话变化，契约只写通用规则。

## 5. 契约条款

### C1 `run_suite --out` 根校验

- 前置：`run_suite.py --out`。
- 后置：输出路径必须 realpath 在仓库根内；越界 `../` 立即 FAIL；测试覆盖 `--out ../escaped.json`。
- 失败：越界写出仓库外、未校验 → FAIL。
- 不变式：测试产物不得写出仓库根。

### C2 failure log 密钥扫描

- 前置：`check_roles` failure log。
- 后置：`check_failure_log` 调 `check_secret_scan`；复用 v4.7.0 C13 模式（`API_KEY`、`TOKEN`、`PASSWORD`、`SECRET` 变量赋值）；注入 → FAIL；无失败记录 → PASS。
- 失败：failure log 含密钥仍 PASS → FAIL。
- 不变式：五类报告统一密钥扫描。

### C3 pre-commit hook 目录校验

- 前置：`pre_commit_check.py install-hooks`。
- 后置：hook 目录必须 realpath 在仓库根内；`core.hooksPath` 越界 → FAIL；测试覆盖绝对路径越界。
- 失败：可写仓库外 hook → FAIL。
- 不变式：hook 目录不得越界。

### C4 `check_text` 路径包含校验

- 前置：`check_text.py --root/--retro/--git-push`。
- 后置：三路径必须 realpath 在仓库根内；越界 → FAIL；测试覆盖 `../`。
- 失败：越界读/写 → FAIL。
- 不变式：只读也不得越界。

### C5 CI action pin + 引号

- 前置：`.github/workflows/ship-it-gates.yml`。
- 后置：action 使用完整 SHA；`for spec in "$CHANGED"` 或数组安全展开；测试扫描 YAML。
- 失败：浮动 tag、未引号变量 → FAIL。
- 不变式：CI 供应链可复现。

### C6 `default_base` 死代码

- 前置：`pre_commit_check.py`。
- 后置：删除 `default_base` 死代码；`base=HEAD` 与文档一致；测试覆盖。
- 失败：死代码/文档不一致 → FAIL。
- 不变式：代码与文档一致。

### C7 guard restore 真实性

- 前置：`guard_large_write.py restore`。
- 后置：manifest 含工具生成 `hmac`（HMAC-SHA256；key 从 `~/.dsh/guard.key` 或 `GUARD_KEY`）；restore 校验 hmac；手写缺/错 → FAIL；测试覆盖。
- 失败：手写 manifest 可 restore → FAIL。
- 不变式：restore 只信工具生成 manifest。

### C8 reviewer 派发/唤醒

- 前置：每个 step 的 reviewer。
- 后置：`ship-it/SKILL.md`/`team-mode.md` 写明主脑必须在派发/返回/检查点唤醒 reviewer；`check_roles start/verify` 检查 `auditor-patrol` 的 `reviewer_dispatch` 字段（每 step 唤醒记录）；缺失 FAIL；测试覆盖。
- 失败：主脑未派发/未唤醒且无 `reviewer_dispatch` 证据（C8）→ FAIL。
- 不变式：reviewer 是唯一汇总接口；机器闸门拦遗漏。

### C9 Step 9 清理

- 前置：交付前。
- 后置：删除 `tmp/`、`.tmp/`、`.dsh-project-memory/`、`tests/__pycache__/`、test 分支临时文件（`test/**/*.tmp`、`*.gz`）；`git status` clean；pre-commit hook 文档说明；测试覆盖。
- 失败：残留/未说明 hook → FAIL。
- 不变式：清理零容忍。

### C10 版本同步

- 前置：v4.7.2 发布前。
- 后置：`ship-it/SKILL.md`、`ship-it/CHANGELOG.md`、根 `CHANGELOG.md` 三处 4.7.2；`check_docs` EXPECTED_VERSION=4.7.2；测试覆盖。
- 失败：三处不一致/check_docs 未改 → FAIL。
- 不变式：版本三处一致。

### C11 验证

- 前置：C1–C10、C12、C13、C14 完成。
- 后置：`check_text`/`check_docs`/`check_spec`/`check_roles` + 全量测试 + J1/J3/J4/security/auditor + 用户验收。
- 失败：任一非零 → FAIL。
- 不变式：未验收不进入 PR。

### C12 reviewer 唯一汇总枢纽（本 spec 核心）

- 前置：角色派发后、报告/汇总阶段。
- 后置：派发可直连（主脑→角色）；报告必经 reviewer（角色→reviewer→主脑）；主脑直收由 patrol 记录+裁判员判定。reviewer 每 1 分钟巡检（schedule_create 会话态，证据=patrol 轮次时间戳）。auditor-patrol 记录 reviewer_dispatch_at（首次派发，C12① 专用）、heartbeat_effective_at（当前心跳机制生效时间，C12② 专用）、role_dispatch（结构见 C13）、last_active_at、汇总来源（角色→报告路径）。check_roles 校验：① reviewer_dispatch_at < min(非 reviewer 角色 role_dispatch.dispatch_at)，reviewer 自身豁免；② 只对 heartbeat_effective_at 之后轮次校验相邻 Δ≤60s，此前轮次不参与、不追溯；暂停段（schedule_edit active:false）不计入、patrol 记 pause/resume、跨暂停不参与 Δ；末轮不早于 max(first_write_at,test_run_finished)−60s；③ 汇总来源覆盖 dev/tester/security/referee/auditor 五角色。C8=字段存在性，C12=顺序/间隔/覆盖度。
- 失败：reviewer 晚于非 reviewer 角色派发、heartbeat_effective_at 之后轮次 Δ>60s、末轮新鲜度不足、汇总缺角色、主脑直收（裁判员判定）→ FAIL。
- 不变式：reviewer 唯一汇总枢纽；派发可直连，报告必经 reviewer；机器判顺序/间隔/覆盖，裁判员判直收。
### C13 角色复用优先（不新开）

- 前置：任何角色派发。
- 后置：默认复用现有角色（`send_message` 唤醒，保留上下文，节省 token）；新开（`subagent`）仅限四种：角色缺失(`new_missing`)、上下文溢出(`new_overflow`)、需独立无记忆视角(`new_independent`)、v4.7.0 C17 失败换人(`new_replace`)。`auditor-patrol` 的 `role_dispatch` 统一定义为 `{角色: {dispatch_at, source}}`，source 取值 reuse/new_missing/new_overflow/new_independent/new_replace；新建时必须附理由字段。`check_roles` 机器校验：source 取值合法、新建附理由；理由合理性由裁判员判定（非机器）。
- 失败：source 取值非法、新建无理由 → FAIL；复用却标 new_* 由裁判员判定（非机器）。
- 不变式：复用优先，新开例外且记录理由；机器验字段，裁判员验合理性。
### C14 主脑不打扰用户

- 前置：主脑与用户交互。
- 后置：签约/验收提醒按 v4.7.0 C1/C2 各发送一次，之后不重复催促；其余场景被动响应（步骤完成汇报除外，按 ship-it 9 步执行）。心跳提醒可能对用户可见（schedule_create reminder 投递到 session）；仅在 dev/tester 活跃期启用、间隙暂停、不重复发送相同状态的进度消息；异常或用户询问时才主动通知。机器项=文档断言（SKILL.md/team-mode 写明上述规则）；行为由用户/裁判员判定（非机器）。
- 失败：文档缺规则、重复催促、心跳向用户发消息、重复进度 → FAIL；实际行为由裁判员判定。
- 不变式：提醒各一次，之后被动；心跳内部静默；异常才主动。
