# v5.2.1 测试与脚本修复

## 1. 背景与目标

v5.2.1 发布后测试与脚本存在 7 处不同步（路径/版本/语义/编码/转义/残留），导致 CI 假绿。详细问题分析见方案分析 `docs/reviews/2026-11-27-v5.2.1-test-fixes-analysis.html`。目标：修复后本机与 CI 都真实绿，不破坏既有契约语义。

### 需求澄清记录

- **原始需求**：用户说"修复，然后肯定是要，都修复什么怎么修复提供方案啊 走新版本的ship-it 流程。先单干"
- **优化后需求**：修复上游 7 个已知问题（测试路径硬编码、版本硬编码、c18 fixture、run_suite 返回码、local_check 编码、check_docs 转义、outside.md 残留），使测试与脚本与 v5.2.1 对齐
- **优化说明**：联网搜索确认上游无 open issues；盘点测试文件发现 36 处硬编码；确认 run_suite 返回码语义会掩盖 FAIL
- **用户问答（分轮决策清单）**：
  - R1：查验了修复范围/是否提 PR/版本策略三个关键决策（详见方案分析 `docs/reviews/2026-11-27-v5.2.1-test-fixes-analysis.html`）→ 据此提问：用 ask_user_question 一次性问三个决策 → 用户答：B 修上游源码 + B 本地修+提 PR + A 动态读 SKILL.md
- **用户约束**：未找到（本项目无 AGENTS.md / runbook 红线）
- **决策展示记录**：三个决策已在 ask_user_question 完整列出，用户逐一选择
- **四零件清晰度自评**（C10）：角色 高、任务 高、背景 高、要求 高

## 2. 方案自审

### 2.1 复用盘点

既有测试框架（unittest + run_suite.py）、校验脚本（check_spec/check_docs/check_text/local_check）。

### 2.2 决策

**B 扩展**：修既有测试和脚本，不改契约语义。放弃"重写测试框架"的彻底解耦（没必要，问题只是路径/版本/语义不同步）。

### 2.3 解决方案

**方案 1：测试路径对齐（问题 1）**
- 修法：把所有 `docs/specs/` 改为 `ship-it/docs/specs/`
- 改动：`tests/test_process_gates.py` 第 1752/1769/1793/2445/2453/3002 行，6 处路径字符串
- 为什么：v5.2.1 已把 spec 统一到 `ship-it/docs/specs/`，测试必须跟随

**方案 2：版本动态读取（问题 2）**
- 修法：测试和 `check_docs` 从 SKILL.md frontmatter 动态读版本，不再硬编码
- 改动：`tests/test_process_gates.py` 第 2758/1819 行，改为动态读取
- 为什么：SKILL.md 是唯一事实源，动态读避免下次版本升级再漂移

**方案 3：c18 fixture 补全（问题 3）**
- 修法：测试 fixture 里补写 `ship-it/SKILL.md`
- 改动：`tests/test_process_gates.py` 第 2193–2197 行，补 1 行
- 为什么：`check_docs` 需要读 SKILL.md 的版本，fixture 必须完整

**方案 4：run_suite 返回码语义修正（问题 4）**
- 修法：有 FAIL/ERROR 就返回 1，只有纯 SKIP（无 FAIL/ERROR）才返回 2
- 改动：`tests/run_suite.py` 第 250–252 行
- 为什么：FAIL 优先级高于 SKIP，避免 CI 假绿

**方案 5：local_check 编码兜底（问题 5）**
- 修法：加 `errors="replace"`
- 改动：`ship-it/scripts/local_check.py` 第 65 行
- 为什么：解码失败时用 `` 替代，不崩溃

**方案 6：check_docs 转义修复（问题 6）**
- 修法：docstring 改为 raw string
- 改动：`ship-it/scripts/check_docs.py` 第 242 行
- 为什么：raw string 里 `\d` 是字面量，不告警

**方案 7：测试残留清理（问题 7）**
- 修法：测试结束后用 try/finally 清理
- 改动：`tests/test_process_gates.py` 第 2717 行附近
- 为什么：确保测试结束（无论成功失败）都清理

## 5. 契约条款

### C1 测试路径对齐
- **前置**：v5.2.1 已把 spec 统一到 `ship-it/docs/specs/`
- **后置**：所有测试里的 `docs/specs/` 改为 `ship-it/docs/specs/`
- **失败**：测试因 FileNotFoundError 报错
- **不变式**：测试文件数不变，只改路径字符串

### C2 版本动态读取
- **前置**：SKILL.md frontmatter 有 `version` 字段
- **后置**：测试和 check_docs 从 SKILL.md 动态读版本，不再硬编码
- **失败**：测试断言版本不匹配
- **不变式**：SKILL.md 是唯一事实源

### C3 run_suite 返回码语义
- **前置**：`run_suite.py:250-252` 有 SKIP 就 return 2
- **后置**：有 FAIL/ERROR 就 return 1，只有纯 SKIP（无 FAIL/ERROR）才 return 2
- **失败**：CI 假绿（有 FAIL 但返回 2 被当通过）
- **不变式**：0 = 全过，1 = 有失败，2 = 有 SKIP 但无失败

### C4 local_check 编码兜底
- **前置**：`local_check.py:65` 用 `text=True, encoding="utf-8"` 无 `errors` 参数
- **后置**：加 `errors="replace"`，解码失败不崩溃
- **失败**：中文 Windows 下子进程输出解码崩溃
- **不变式**：CI（UTF-8 环境）行为不变

### C5 check_docs 转义告警
- **前置**：`check_docs.py:242` docstring 有 `\d` 无效转义
- **后置**：改为 raw string 或 `\\d`
- **失败**：Python 3.12+ 每次运行都告警
- **不变式**：正则语义不变

### C6 测试残留清理
- **前置**：`test_process_gates.py:2717` 写 `root.parent / "outside.md"`
- **后置**：测试结束后清理，或改用临时目录
- **失败**：`git status` 出现 `?? outside.md`
- **不变式**：测试逻辑不变

### C7 方案分析产出物（必须）
- **前置**：需求分析员完成问题分析与方案推导
- **后置**：`docs/reviews/2026-11-27-v5.2.1-test-fixes-analysis.html` 存在且包含决策树结构标记（选项/推荐/决策树/理由 ≥2 个）
- **失败**：`check_spec.py --stage draft` 报 C9[A5-C] 错误
- **不变式**：方案分析产出物是 spec 的附件，改动 = spec 改动 = 重新签约

### C8 可视化修复报告（必须）
- **前置**：修复完成后，生成可视化修复报告
- **后置**：`docs/reviews/2026-11-27-v5.2.1-test-fixes-report.html` 存在且包含：
  - 分区清楚（问题/方案/改动/验证 四个区块）
  - 前端问题：before/after 代码对比演示（高亮 diff）
  - 后端问题：逻辑流程图（Mermaid 或 SVG）或数据流图
  - 每个改动都有"改了什么/为什么改/怎么验证"三要素
- **失败**：报告文件不存在或缺少必要区块
- **不变式**：修复报告与契约条款一一对应（C1→区块1，C2→区块2...）
