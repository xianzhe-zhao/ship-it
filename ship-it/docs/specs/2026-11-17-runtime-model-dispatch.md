## 1. 背景与目标（what & why）

**现状**：团队模式模型分配是「runbook 静态绑定」——角色 → 模型写在项目 runbook「角色分配」表里，派发按表执行。三个实测痛点（2026-11-17 本会话亲历）：

1. **配置一变就要人工改表**：宿主模型池/白名单变动、促销到期、换环境，都得有人更新分配表，否则派发失败或分配已下线模型（用户原话：「每次调整也不是办法」）。
2. **会话策略固化让静态表失效**：DSH `allowedModels` 在会话创建时固化，本会话 `dsh-b6f0b86e-6954` 实测 qwen4-max-preview / qwen3.6-flash 两条路由被拒（当前配置白名单已含二者）——静态表写的模型在本会话根本派不出去。
3. **表与实际路由漂移**：本会话实测发现 deepseek-account provider（deepseek-v4-pro / deepseek-flash）可派发但 runbook 未记录；家用节还标着「本机未实测/冻结」。

**为什么要改**：把「派发时用哪个模型」的决策从**静态配置**移到**运行时**——以本会话实际放行的路由为准，默认让宿主路由决定，仅硬能力不满足或用户显式要求时才动态挑选。runbook 回归「能力注册表」本职（记能力/成本/实测证据），不再维护角色 → 模型绑定。

**改完是什么样**：子代理派发默认不指定模型（宿主默认路由/继承会话模型）；测试员需读图而默认模型不支持、或用户显式要求省钱/指定模型时，主脑查本会话放行集合按能力+性价比显式挑选；路由不可用自动回退并在汇报注明，不停摆、不每次问用户；runbook 删除两处「角色分配」表，保留能力清单并写回本次实测。

## 5. 契约条款（C1 / C2 / …）

### C1 默认路由优先派发

- **前置条件**：主脑向任一角色派发 subagent，且该角色硬能力被默认模型满足（或无硬能力要求）、用户无显式模型要求。
- **后置条件**：派发**不指定 provider/model**，由宿主默认路由决定（DSH：`subagent`/`subagent_fork` 无模型参数走默认路由，`spawn_teammate` 继承主脑会话模型）；prompt 仍含既有三要素（spec 条款号 / 文件作用域 / 自检要求）。
- **失败行为**：默认路由派发失败 → 按 C5 自动回退，不停摆问用户。
- **不变式**：主脑 = 用户选择的会话模型，固定不分配；默认派发不改变「skill 正文零模型名」规则。

### C2 动态挑选仅限两类触发且先过硬能力过滤

- **前置条件**：① 角色硬能力不被默认模型满足（当前唯一硬要求：测试员图像输入），或 ② 用户显式要求（省钱 / 指定模型）。
- **后置条件**：主脑用 `list_subagent_models` 查**本会话实际放行集合**，按硬要求 > 软要求 > 性价比过滤排序，经宿主按调用指定模型入口（DSH：`workflow` 的 `agent(prompt,{provider,model})`）显式派发；挑选结果 + 理由（能力 + 成本）写入当步汇报。
- **失败行为**：放行集合中无满足硬能力的模型 → 测试员降级为主脑亲自核验截图（既有规则），注明；用户显式指定的模型未放行 → 如实报告原因（两类报错含义）+ 给替代建议，不静默换模型。
- **不变式**：成本不得覆盖硬能力要求 🔒；动态挑选不得替代 prompt 中的 spec 条款号。

### C3 测试员图像硬要求与实测为证原样保留 🔒

- **前置条件**：任何派发决策涉及测试员角色。
- **后置条件**：「必须图像输入」硬要求与「实测为证」（声称不支持前必须先发探针图实测，降级附失败证据）条文在 team-mode.md 中**保留不变**；默认派发时默认模型图像能力未知 → 先探针再决定是否触发 C2 动态选。
- **失败行为**：未实测即声称不支持并降级 = 违规（既有失败处理表行保留）。
- **不变式**：本次机制变更不放宽任何 🔒 业务事实；无探针证据不可降级。

### C4 runbook 删除角色分配表并补记默认路由

- **前置条件**：修改 `docs/deploy-runbook.md` 与 team-mode.md 注册表模板。
- **后置条件**：runbook 删除「角色分配 · 办公环境」「角色分配 · 家用环境」两节及模板中角色分配行；保留模型能力清单（含成本列）、环境识别、价位折扣、场景选型建议；每个环境节补记**默认路由**（宿主 `agent-default-model` / 会话模型）；team-mode.md 注册表模板同步删除分配行。
- **失败行为**：runbook 或模板残留角色 → 模型分配表 → 校验 FAIL。
- **不变式**：模型名仍只存在于 runbook（skill 正文零模型名 🔒）；能力清单是动态挑选的**能力参考**，不是绑定分配。

### C5 路由不可用自动回退

- **前置条件**：派发路由不可用（会话策略固化 / 网关故障 / 模型下线 / 派发失败）。
- **后置条件**：自动切换到下一个满足该角色能力的放行候选；无候选 → 主脑自做（测试员 → 主脑核验截图降级）；汇报注明「模型回退」及原因；**不停摆、不每次问用户**。
- **失败行为**：回退链穷尽仍失败 → 遇阻即停报用户（既有失败处理表语义）。
- **不变式**：回退不得绕过硬能力（测试员回退模型仍须图像输入，否则走主脑核验降级）；同类派发失败一次后主脑自己做，不再重派（反越权红线 #6 保留）。

### C6 运行时放行以本会话实测为准

- **前置条件**：任何派发决策（默认或动态）。
- **后置条件**：决策依据 = 本会话 `list_subagent_models` 实测放行状态，**不是**配置文件静态白名单、也不是 runbook「可派发」列（后者仅为历史实测证据记录，须注明验证会话与日期）；两类报错处理沿用 v4.4.0：`has no configured model` = 模型池无此 ID（改 ID）；`not allowed for this Session` = 会话白名单固化（提示新开会话，不反复改配置）。
- **失败行为**：`list_subagent_models` 不可用 → 读宿主配置并注明「能力信息可能过期」；默认路由优先派发不受影响（不依赖该工具）。
- **不变式**：会话策略固化机制表述与 v4.4.0 spec C8 / runbook 一致，不产生第二种口径。
